줄 정렬

알파벳순, 길이순, 역순 또는 셔플 — 자연수 정렬 및 로케일 인식 정렬.

알파벳순은 하나의 것이 아닙니다

정렬은 실제 데이터를 정렬할 때까지 해결된 문제처럼 보입니다. 단순 정렬은 코드 포인트를 비교하여 모든 대문자를 모든 소문자 앞에 놓습니다 — 그래서 "Zebra"가 "apple"보다 먼저 정렬되고, 이름 목록은 어떤 인간도 알파벳순이라 부르지 않는 순서로 나옵니다.

이 도구는 대신 로케일 인식 정렬을 사용하며, 이는 운영 체제가 파일 목록을 정렬하는 데 사용하는 것과 같은 메커니즘입니다. 악센트가 있는 문자는 끝이 아닌 기본 문자 옆에 정렬되고, 대소문자는 기본적으로 무시됩니다. 이것이 사람들이 알파벳순이라고 의미하는 것이기 때문입니다.

자연수 순서는 또 다른 일반적인 놀라움입니다. 텍스트로 비교하면 "항목 10"이 "항목 2"보다 먼저 정렬됩니다. "1"이 "2"보다 작기 때문입니다. 자연수 순서는 숫자 부분을 숫자로 비교하여 항목 1, 항목 2, 항목 10을 제공합니다. 숫자가 포함된 모든 것에 켜둔 상태로 두세요.

정렬 모드

  • 알파벳순 — 로케일 인식, 기본적으로 대소문자 무시. 내림차순으로 Z에서 A로 변경 가능.
  • 줄 길이순 — 가장 짧은 것이 먼저, 동점은 알파벳순으로 해결. 키워드나 헤드라인 목록에서 이상값을 찾는 데 유용.
  • 현재 순서 반전 — 정렬하지 않고 목록을 뒤집기. 시간순 로그에 일반적으로 필요한 것.
  • 셔플 — Fisher–Yates 셔플로, 모든 순서가 동일한 확률. 무작위 비교기를 사용하는 단순 셔플은 편향됩니다.

빈 줄은 기본적으로 삭제됩니다. 한쪽 끝에 공백 블록이 있는 정렬된 목록은 거의 아무도 원하지 않는 것이기 때문입니다. 빈 줄에 의미가 있다면 끄세요.

자주 묻는 질문

왜 제 목록이 대문자가 먼저 정렬되었나요?

이것은 원시 문자 코드를 비교하는 도구에서 발생합니다. 모든 대문자가 모든 소문자보다 앞에 옵니다. 이 도구는 로케일 인식 정렬을 사용하고 기본적으로 대소문자를 무시하므로, 사람이 기대하는 순서를 얻게 됩니다. 엄격한 버전이 필요한 경우 "대소문자 구분"을 켜세요.

왜 항목 10이 항목 2보다 먼저 오나요?

텍스트로 비교하면 "1"은 "2"보다 작으므로, "항목 10"이 먼저 정렬됩니다. "자연수 순서"를 켜면 숫자 부분이 숫자로 비교되어 항목 1, 항목 2, 항목 10이 됩니다. 기본적으로 켜져 있습니다.

셔플이 정말로 무작위인가요?

모든 가능한 순서가 동일한 확률로 발생하는 Fisher-Yates 셔플을 사용합니다. 무작위 비교 함수를 정렬 함수에 전달하여 셔플하는 것은 일반적인 방법이며 편향된 결과를 측정 가능하게 만듭니다.
