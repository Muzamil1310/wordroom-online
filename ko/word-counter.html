단어 수 세기

실시간 카운트, 학술 제외 기능 및 인도어/CJK 스크립트의 올바른 세그멘테이션 지원.

단어 세기가 실제로 어떻게 작동하는지

단어 카운터는 하나의 단어가 끝나고 다음이 시작되는 곳을 결정해야 합니다. 영어의 경우 이것은 사소한 것처럼 보입니다 — 공백으로 분할하기 — 그래서 거의 모든 온라인 카운터가 정확히 그렇게 하고, 그래서 세계의 대부분에 대해 거의 모든 것이 틀립니다.

공백으로 분할하는 것은 라틴 스크립트 밖에서는 즉시 실패합니다. 중국어와 일본어는 단어 사이에 공백을 넣지 않습니다. 태국어도 마찬가지입니다. 텔루구어, 힌디어, 타밀어는 공백을 사용하지만, 단순한 카운터가 별도의 문자로 잘못 세는 결합 기호도 사용합니다. 이 도구는 대신 브라우저에 내장된 Unicode 세그멘테이션을 사용하며, 감지된 스크립트에 적절한 단어 경계 규칙을 적용합니다.

문자 세기에도 같은 함정이 있습니다. JavaScript 식 "నమస్తే".length는 6을 반환합니다. 독자가 인식하는 문자가 아니라 UTF-16 코드 단위를 세기 때문입니다. 단일 이모지는 2를 반환할 수 있고, 국기 이모지는 4를 반환할 수 있습니다. 이 도구는 그래프 클러스터를 세므로, 화면에서 세는 것과 일치합니다.

단어 제한과 평가자가 세는 것

학술적 단어 제한은 사람들이 카운터를 사용하는 가장 일반적인 이유이며, 워드 프로세서가 보고하는 숫자는 평가될 숫자가 아닌 경우가 빈번합니다. 기관마다 다르지만, 일반적인 패턴은 본문은 세이고 구조는 세이지 않는다는 것입니다.

학술 모드에서 각 요소를 끌 수 있으며, 원본 합계와 세기 가능한 합계를 모두 표시하여 안내서에서 지정한 것에 맞출 수 있게 합니다. 규칙이 모호할 때는 안내서가 우선합니다. 이 도구는 일반적인 관례를 모델링하며, 귀하의 특정 기관의 정책이 아닙니다.

읽기 시간과 말하기 시간

여기서 사용되는 읽기 시간은 분당 238단어로, Brysbaert의 2019년 190개 연구 메타분석에서 발견된 영어 산문의 평균 무성독서 속도입니다. 많은 사이트가 숫자의 출처를 말하지 않고 200 또는 250을 사용합니다. 3,000단어 기사에서의 차이는 2분 이상입니다.

말하기 시간은 의도적으로 보수적인 분당 130단어를 사용합니다. 이는 대화 속도보다 느립니다. 발표자는 긴장할 때 준비된 텍스트를 빨리 읽는 경향이 있으며, 분당 150단어를 가정하는 리허설 타이밍은 시간을 초과하는 경향이 있습니다. 연설의 시간을 재는 경우, 이 숫자를 최소로 취하고 소리 내어 리허설하세요.

양쪽 숫자는 독자와 텍스트 유형의 평균입니다. 밀도 높은 기술 산문은 천천히 읽힙니다. 익숙한 내러티브는 빨리 읽힙니다.

자주 묻는 질문

단어 수에 인용문과 참고문헌이 포함되나요?

소속 기관에 따라 다르며, 이 도구는 두 가지 관례를 모두 지원합니다. 참고문헌 목록은 거의 항상 단어 제한에서 제외됩니다. 본문 내 인용은 많은 대학에서 제외되지만 전부는 아닙니다. 학술 모드에서 관련 제외를 활성화하고 원본 합계와 카운트 가능한 합계를 비교하세요. 과정 안내서가 최종 권위입니다.

제 텍스트가 어디에 업로드되나요?

아닙니다. 모든 계산은 JavaScript를 사용하여 브라우저에서 실행됩니다. 텍스트를 수신하는 서버도, 계정도, 입력 내용에 대한 분석도 없습니다. 브라우저의 네트워크 탭을 열어 확인할 수 있습니다. 페이지 로드 후 전송되는 것은 없습니다.

문자 수가 Microsoft Word와 다른 이유는 무엇인가요?

Word는 일부 컨텍스트에서 UTF-16 코드 단위를 세어 이모지, 인도계 스크립트 및 기본 라틴 범위를 벗어나는 기타 문자의 수를 부풀립니다. 이 도구는 그래프eme 클러스터를 셉니다. 즉, 독자가 인식하는 문자 단위입니다. 순수 영어 텍스트에서는 두 값이 일치합니다.

독서 시간은 어떻게 계산되나요?

Brysbaert의 2019년 메타분석에서 영어 산문의 평균 무독 속도인 분당 238단어로 나눕니다. 말하기 시간은 의도적으로 보수적인 분당 130단어를 사용합니다.

텔루구어나 힌디어 단어를 올바르게 셉니까?

예. 도구는 스크립트를 감지하고 공백으로 분할하는 대신 해당 스크립트의 Unicode 단어 경계 규칙을 적용합니다. 결합 기호와 결합 자가 올바르게 처리됩니다. 혼합 스크립트 문서는 지배적인 비라틴 스크립트의 규칙으로 계산됩니다.
